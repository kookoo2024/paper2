# 知学网阅卷助手

AI自动批改主观题，支持自动提交分数。

## 快速开始

### 1. 安装依赖
```bash
pip install -r requirements.txt
```

### 2. 准备配置
把 `zhixue_simple_config.example.json` 复制为 `zhixue_simple_config.json`（该文件已被 .gitignore 忽略，**API Key 只放这里，千万不要提交到 GitHub**）。

### 3. 运行程序
- **推荐**：双击 `start.pyw`（不弹黑窗口）；或运行一次 `make_shortcut.bat`，以后点桌面的「阅卷」。
- 调试时用 `python zhixue_simple.py`（带命令行窗口，能看到报错）。
- 无窗口模式下的报错写在 `run.log`。

## 使用步骤

### 首次使用（需要设置）

1. **设置答案区域**
   - 点击「框选」按钮
   - 拖动鼠标框选学生答案区域

2. **输入题目信息**
   - 题号：如 17
   - 满分：如 15
   - 参考答案：手动输入或点击「截图识别」

3. **设置自动提交**
   - 点击「定位」按钮
   - 按提示依次设置：分数输入框位置、提交按钮位置

4. **测试功能**
   - 点击「测试」按钮
   - 检查是否正确输入分数并点击提交

### 日常使用（自动记忆）

程序会自动记忆上次的设置，直接使用即可：

1. **安全模式**（需要确认）
   - 勾选：✓ 连续 + ✓ 自动填分
   - 按空格键开始批改
   - 每次弹窗确认分数（Enter接受 / Esc拒绝）
   - 效率：500-700份/小时

2. **高效模式**（跳过确认）⚡
   - 勾选：✓ 连续 + ✓ 自动填分 + ✓ 跳过确认
   - 按空格键开始批改
   - 自动提交，无需确认
   - 效率：900-1200份/小时

## 接入本机 Magpie（推荐）

[magpie](https://usemagpie.ai) 是本机的模型网关（127.0.0.1:3425），在 magpie 里配好 Gemini / DeepSeek / Qwen / Ollama 等，本程序只连 magpie 一个地址，Key 都留在 magpie 里。

1. 打开 magpie 应用（或命令行 `magpie serve`），在里面添加至少一个**能识图**的模型（如 Gemini 2.5 Flash、Qwen-VL）
2. 本程序点「模型设置」→ 提供商选 **Magpie** → 自动检测并获取模型列表
3. 选一个能识图的模型 → 保存。API Key 默认 `magpie-zhixue`（本机任意值都行，用来在 magpie 的 Usage 里区分本程序的调用）

## 在线更新

- 程序启动 3 秒后会静默检查一次，有新版本时右上角 ⬆ 变红「⬆新」；也可以随时点 ⬆ 手动检查
- 更新源：GitHub 原始地址，连不上自动换 jsDelivr 镜像；可在配置里加 `"update_url": "你的地址/"` 改成自己的服务器
- 只下载 `version.json` 里列出的文件，逐个校验 sha256 和语法，**绝不覆盖你的配置文件**；旧文件备份在 `backup/` 文件夹
- 不想自动检查：配置里加 `"auto_check_update": false`

**发布新版本**（开发者）：改 `APP_VERSION` → 运行 `python make_release.py` 重新生成 `version.json` → 提交推送到 main。

## 批改准确性（v1.3.0）
- **给分点**：点 ② 里的「编辑答案」打开大窗口，左边写参考答案，右边写给分点，每行一条：`求出斜率 k=2｜2分`。参考答案里写了「（2分）」的，可点「从答案提取」自动生成。不填时模型会先从参考答案里拆出给分点。
- **按点得分**：模型逐条给分，总分由程序相加（不再用“满分减扣分”），并按「可给0.5」取整。
- **先转写再判分**：结果区显示模型识别出的学生原文，看错字一眼能发现；看不清会标【看不清】。
- **强制人工确认**：把握度低、有看不清、用了其他解法、给分点合计≠满分、模型总分与逐点相加不一致时，即使勾了跳过确认也会弹窗。
- **空白卷**：答题区域几乎没有墨迹时直接判 0 分，不调用模型（阈值 `blank_threshold`，默认 0.0015，可在配置文件里改）。
- 截图四周自动多留 6 像素，避免切掉边上的字。

## 原题 + 批改指南（v1.12.0）

备课时每道题做一次，批改时不多调用模型、不变慢。

1. 打开「参考答案与给分点」编辑窗口，在下方「原题」点 **截原题**，框住题目：截图会保存，题目自动转成统一格式的文字（请核对一遍）。
2. 参考答案可以用「截图识别」或「粘贴」，截图识别会直接按统一格式输出。
3. 在「批改指南」点 **生成指南**：AI 看着原题，把参考答案整理成统一格式，并给每个得分步骤写「必须看到 / 等价也对 / 部分给分 / 常见错误」。
4. 预览窗口里先核对：程序会比对整理前后的每个分值，对不上就默认不替换参考答案；指南里出现标准外的分值也会标红。确认后才生效，替换后在答案框按 Ctrl+Z 可撤销。
5. 批改时，原题和已确认的指南会和评分卡一起发给模型，仍然一次请求。原题、答案、给分点、满分任何一项改过，指南就显示「已过期」，批改时自动不用，需要重新生成。

统一格式：文字用中文，式子一律写成 $LaTeX$；小问写（1）（2）；每个得分步骤一行，行尾写“（N分）”；多解法写“解法二：”；评分说明放最后。

## v1.7.3（2026-11-11）

- **给分点不再被截断**：以前自动拆出的给分点只保留 28～40 字，`解得 k=15/8`、`EF 方程 x+4y+12=0` 这类关键结论会被截掉，模型只能凭印象给分。现在保留每个分问的起点和最终结论，按你给的评分标准逐条对照。
- **手动粘贴的给分点也能认**：像“求出直线 AB 的方程 15x−8y−55=0（2分）”这种超过 20 字的长给分点，现在也能识别；“本题满分 15 分”“参考答案共 15 分”这类汇总说明不会被误当成给分点。
- **评分更严格**：写出该点要求的公式、方程或结论才给分；只写思路、没算出结果最多给一半；该点结论错误不得给满；拿不准时按未完成处理，不替学生补步骤。
- **等价解法不再误判 0 分**：第(2)问用切点弦/极点极线直接写 `(x₀−a)(x−a)+(y₀−b)(y−b)=r²`，和“四点共圆、两圆相减”同样给分。
- **自动裁掉截图底部的 Windows 任务栏**：任务栏图标会干扰识图；程序只在底部整段“又暗又彩”时裁掉，白底手写和纯黑图不会误裁。
- **多次判分改为取中位数**：每份固定判 3 次，取中间分，不再取最高分，减少“越判越松”。
- 单份实测约 9～10 秒，仍在 20 秒以内。

## v1.7.4（2026-11-11）

- **只判一次**：取消“每份判 3 次取中位数”，每份只请求一次模型，判完即用，更快也更省额度。
- **严格按给分点给分**：只有写出该点要求的公式、方程或结论（或数学上等价的正确表达）才给分；没看到得分点、也没有等价表达，或只写思路、跳步、结论写错，一律 0 分，不再给“思路分/步骤分/同情分”。
- **不许模型改分值**：返回的给分点条数和分值必须与评分标准一致，模型改动会被程序回填并提示复核。
- **取整只向下**：不再四舍五入凑分，例如 12.5 分按 12 分计。
- **取消逐份人工复核**：把握度低、看不清、等价解法等情况不再强制弹窗，判完直接提交；“跳过确认”默认勾选，需要把关时可手动取消。
- 「参考答案」编辑窗口新增「粘贴」按钮：剪贴板文字一键填入或追加，图片请用「截图识别」。

## v1.7.5（2026-11-16）

- **修复累计分被当成满分相加**：像「1分、3分、4分…17分」这种累计写法，以前会按每点满分累加成 92 分。现在自动识别为累计分并换算成每步增量（1+2+1+…=17），日志里会打印换算过程。
- **模型也拦一道**：即使模型仍按累计分返回，程序也会换算成增量再计分，不会出现超过满分的合计。
- **评分标准可从参考答案读取**：给分点留空时，先尝试解析参考答案里的评分标准（含累计分），解析不到才自动拆。
- **markdown 标题不再误当给分点**：「### （1）证明…（4分）」这类分块小计会被跳过；进入「参考解答」段落后不再把解答文字当给分点。
- **超过满分直接提示**：逐点合计大于满分时按满分封顶，并明确提示检查是否写成了累计分。

- **只允许 0 分或满分**：除标准明确写出的“扣 N 分”外，模型不能给“写了一半”的部分分；程序会把未授权的部分分改判 0 分，并只允许扣分条款作用于它所属的给分点。

- **小图放大识别**：答卷截图长边小于 1800 时自动放大到最多 2.5 倍，改善小字、负号和最终答案的识别；转写上限提高到 600 字，避免最后结论被截掉。

- **回归测试**：新增 `eval.py`，按 `eval_cases/用例名/answer.png + expected.json` 批量跑模型，报告总分误差、逐点一致率、误给分率和漏给分率，改提示词前后可直接对比。

## v1.9.1（2026-11-17）

- **评分卡过期自动重建**：答案恢复、换行符变化或旧版本字段导致卡失效时，不再静默退回扁平给分点，而是先按当前标准重建小问/解法/结果点结构。
- **计算题结果点独立给分**：由模型按数学内容判断 `part_type=calculation` 和 `role=result`，程序只允许“本小问最后一步”或老师显式标【结果】的点作为结果点；不再按题面关键词猜“哪个是答案”。
- **证明题认真看方法**：任何方法下，只要证明逻辑完整、条件齐全，就可填 `complete_proof=true` 按该小问满分；不完整、跳步或只写结论的仍按实际完成点计分。
- **等价点仍要原文证据**：未覆盖解法中的等价点必须由模型标记 `equivalent`，并能在学生原文中找到依据；程序不会凭印象补分。
- **回归用例**：已验证完整向量法证明得 4/4、只写正确最终结果得 2 分、错误最终结果仍为 0 分。

## v1.9.2（2026-11-17）

- **完整评分段落**：按句末「(N分)」切段，保留“取中点/建系/写坐标/设点”等上下文，不再只取分值所在那一行；5 分点不会只剩“PD⊥CD”，6 分点不会只剩 M 的坐标。
- **从答案提取不截断**：提取给分点时保留整段证明/计算，不再截成 40 字；累计分自动换算成每步增量。
- **证据覆盖关键步骤**：不再按 checks 条数机械卡人；只拦“只写 λ 的值、没有距离公式”这类结果倒灌，正确的法向量、余弦值不会被误判 0。
- **结果卡更清楚**：评语字号调大，下面按小问列出每个得分点的 `得/满` 分数；结果卡不再显示截图预览。
- **通用分项核对**：每个采分点新增 `checks` 作为核对提示；过程点拿满分时，整点证据要覆盖关键步骤。后续算出的参数、最终数值不能倒灌给前面的过程点。
- **证明与计算分开**：`part_type=proof` 只按完整证明或实际采分点判；`part_type=calculation` 的最后一步才能作为独立结果点。中途点即使被误标成结果点，也不能绕过必要过程。
- **换题型回归**：新增函数最值题，验证“导数法替代配方法”能得 10/10，“只写最大值和最小值”只能拿结果点 2/10；几何题“只写最终结果”仍为 2/17，向量法证明仍为 4/17。
- **截断 JSON 抢救**：模型输出在最后一个字段断掉时，自动补齐字符串和括号，并可从 `parts` 中恢复完整小问，减少 `Expecting ':' delimiter` 直接中断。
- **用时统计修正**：JSON 重试、缺少小问重试的请求时间全部累加到“接口平均”，不再只记最后一次请求。

## v1.10.0（2026-11-17）

- **严格按原标准分档给分**：当参考答案用「1分、3分、4分……17分」这种累计分写标准时，不再拆成 11 个必须逐句对上的小点；每个小问合并成一个分档评分单元。
- **这张 17 分题只保留 3 个评分单元**：第1问允许 `1/3/4` 分，第2问允许 `1/2/4/5/7` 分，第3问允许 `2/4/6` 分；0 分和标准明确写出的扣分档仍可判。
- **不再生成 `checks` 核对项**：去掉逐句关键词式核对，模型先整体判断学生数学上完成到哪一档，再按档位给分；学生换辅助线、换字母、换解法，只要数学上达到该档即可。
- **档位之外不给分**：模型不能自行给 `1.5、3.5` 等原标准没有的分数；只有明确写出“漏负号扣1分”“漏解扣2分”时，才允许出现对应的扣分档。
- **旧评分卡自动迁移**：已保存的 11 点旧评分卡在启动或批改时自动合并成 3 个分档点，不需要重新录入标准。
- **结果卡同步变短**：结果区按小问显示一档一行，例如 `第1问 3/4：①3/4`，不会再列一长串难以对应的细点。
